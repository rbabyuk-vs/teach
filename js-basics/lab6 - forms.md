# Лабораторна робота: форма замовлення в інтернет-магазині

## Мета роботи

Закріпити використання:

- HTML-форм та різних типів полів;
- CSS для оформлення форми та її станів;
- пошуку HTML-елементів через JavaScript;
- подій `submit` і `change`;
- отримання та перевірки введених даних;
- умовних операторів і функцій;
- виведення результату на сторінку.

## Завдання

Спроєктуйте та створіть форму оформлення замовлення для власного інтернет-магазину на **HTML, CSS і Vanilla JavaScript**.

Тематику магазину оберіть самостійно. Наприклад:

- електроніка;
- одяг;
- книжки;
- спортивні товари;
- їжа;
- товари для дому;
- власний варіант.

Ви самі повинні визначити:

- які кроки проходить покупець;
- які дані потрібно запитати;
- які поля є обов’язковими;
- які поля є необов’язковими;
- у якому порядку їх показувати;
- які дані залежать від попереднього вибору;
- які помилки може зробити користувач;
- що відбудеться після успішного оформлення.

Серверну частину створювати не потрібно. Замовлення обробляється тільки у браузері.

---

## Етап 1. Спроєктуйте форму

Перед написанням коду створіть коротку специфікацію.

### 1. Опишіть магазин

```text
Назва магазину:
Що він продає:
Хто його покупець:
Що саме користувач замовляє:
```

### 2. Опишіть flow користувача

Покроково опишіть шлях від відкриття сторінки до успішного замовлення.

Приклад структури:

```text
1. Користувач ...
2. Потім він ...
3. Якщо обрано ..., форма ...
4. Перед надсиланням ...
5. Після успішного надсилання ...
```

Не копіюйте цей приклад як готовий сценарій. Розробіть flow відповідно до власного магазину.

### 3. Визначте дані

Перед реалізацією заповніть таблицю:

| Дані | Для чого потрібні | Тип HTML-поля | Обов’язкові? | Правило перевірки |
|---|---|---|---|---|
| Приклад: email | зв’язок із покупцем | `email` | так | поле не порожнє, правильний формат |
|  |  |  |  |  |
|  |  |  |  |  |
|  |  |  |  |  |

Для кожного обов’язкового поля потрібно вміти пояснити:

> Що станеться, якщо магазин не отримає ці дані?

Не позначайте всі поля обов’язковими без пояснення.

### 4. Визначте стани форми

Опишіть вигляд і поведінку форми у станах:

- початкова порожня форма;
- частково заповнена форма;
- неправильні або відсутні дані;
- успішно оформлене замовлення;
- очищення та повторне заповнення.

### 5. Визначте результат

Опишіть, що користувач побачить після успішного оформлення:

- які дані потраплять у підсумок;
- чи показується загальна вартість;
- чи очищається форма;
- чи можна виправити або повторити замовлення.

## Мінімальні функціональні вимоги

Набір полів студент визначає самостійно, але форма повинна:

1. Містити щонайменше **п’ять змістовних полів**.
2. Використовувати щонайменше **чотири різні типи елементів форми**, наприклад:
   - текстове поле;
   - числове поле;
   - `select`;
   - radio-кнопки;
   - checkbox;
   - `textarea`.
3. Мати щонайменше одне необов’язкове поле.
4. Мати щонайменше одне поле, обов’язковість або видимість якого залежить від іншого вибору.
5. Перевіряти щонайменше три різні правила.
6. Розраховувати вартість замовлення на основі введених даних.
7. Мати кнопку надсилання форми.
8. Мати можливість очистити форму та почати спочатку.
9. Показувати помилки безпосередньо на сторінці.
10. Показувати зрозумілий підсумок успішного замовлення.

---

## Вимоги до HTML

1. Використайте семантичний елемент `form`.
2. Кожне поле повинно мати зрозумілий `label`.
3. Атрибут `for` елемента `label` повинен відповідати `id` поля.
4. Кожне поле, дані якого обробляються, повинно мати атрибут `name`.
5. Згрупуйте пов’язані radio-кнопки за допомогою однакового `name`.
6. Для пов’язаних полів бажано використати `fieldset` і `legend`.
7. Обирайте тип кожного поля відповідно до даних, які воно приймає.
8. Додайте окремі блоки для:
   - повідомлень про помилки;
   - підсумку замовлення.

---

## Вимоги до вигляду

Форма повинна:

1. Бути розміщена в окремому візуальному контейнері.
2. Мати максимальну ширину, щоб поля не розтягувалися на весь великий екран.
3. Мати однакові відступи між полями.
4. Мати добре помітні `label`.
5. Мати однаковий стиль для `input`, `select` і кнопок.
6. Візуально показувати поле у фокусі за допомогою `:focus`.
7. Візуально відрізняти:
   - звичайний стан;
   - стан помилки;
   - успішне повідомлення.
8. Бути зручною для використання на телефоні.
9. Не використовувати Bootstrap або інші CSS-бібліотеки.

Перед написанням HTML зробіть простий ескіз форми на папері або в графічному редакторі. Розташування полів оберіть самостійно відповідно до свого flow.

Важливі зрозумілість, читабельність і зручність, а не декоративна складність.

---

## Поведінка форми

### Залежність між полями

Реалізуйте щонайменше одну логічну залежність між полями. Наприклад, попередній вибір може:

- показувати або приховувати додаткове поле;
- робити поле обов’язковим;
- змінювати доступні варіанти;
- впливати на ціну замовлення.

Конкретну залежність придумайте самостійно та поясніть, навіщо вона потрібна користувачеві.

### Надсилання форми

Для форми потрібно додати обробник події `submit`:

```js
form.addEventListener("submit", function (event) {
  event.preventDefault();

  // Отримання та перевірка даних
});
```

`event.preventDefault()` повинен зупинити стандартне перезавантаження сторінки.

Після натискання **«Оформити замовлення»** програма повинна:

1. Отримати значення всіх полів.
2. Перевірити правильність даних.
3. Якщо є помилка — показати зрозуміле повідомлення.
4. Якщо дані правильні — розрахувати загальну вартість.
5. Показати підсумок замовлення на сторінці.

### Перевірка даних

Правила перевірки мають відповідати таблиці, створеній на етапі проєктування. Перевірте щонайменше три різні умови, наприклад:

- обов’язкове поле не порожнє;
- текст має допустиму довжину;
- число входить у визначений діапазон;
- значення має правильний формат;
- потрібний варіант обрано;
- залежне поле заповнено лише тоді, коли воно потрібне.

Приклади повідомлень, які потрібно адаптувати до власної форми:

```text
Введіть ім’я.
Оберіть товар.
Кількість повинна бути від 1 до 10.
Введіть адресу доставки.
Потрібно погодитися з умовами замовлення.
```

Не використовуйте `alert()` для основних повідомлень. Виводьте їх безпосередньо на сторінці.

### Успішне замовлення

Після успішної перевірки покажіть основні дані, за якими користувач може перевірити своє замовлення, і загальну вартість. Самостійно вирішіть, які дані справді мають бути у підсумку.

Користувацькі дані виводьте через `textContent`, а не через неперевірений `innerHTML`.

### Очищення

Після натискання **«Очистити форму»** потрібно:

- очистити поля;
- повернути залежні поля до початкового стану;
- очистити повідомлення про помилки;
- приховати попередній підсумок.

## Рекомендована структура JavaScript

Назви функцій можуть відрізнятися, але код потрібно розділити на зрозумілі частини.

```js
function getFormData() {
  // Отримує значення полів
}

function validateOrder(data) {
  // Перевіряє дані
}

function calculateTotal(data) {
  // Розраховує загальну вартість
}

function showError(message) {
  // Показує помилку
}

function showOrderSummary(order) {
  // Показує підсумок
}
```

Можна отримувати значення окремо через `.value` і `.checked` або використати `FormData`.

## Один із можливих прикладів

Це лише демонстрація результату. Не потрібно відтворювати саме ці поля, товар або спосіб доставки.

Користувач ввів:

```text
Ім’я: Оксана
Email: oksana@example.com
Товар: Клавіатура
Ціна: 800 грн
Кількість: 2
Доставка: Кур’єрська доставка
Адреса: вул. Шевченка, 10
```

Розрахунок:

```text
800 × 2 + 100 = 1700 грн
```

Очікуваний результат:

```text
Замовлення успішно оформлено

Покупець: Оксана
Email: oksana@example.com
Товар: Клавіатура
Кількість: 2
Доставка: Кур’єрська доставка
Адреса: вул. Шевченка, 10
Загальна вартість: 1700 грн
```

## Захист роботи

Під час захисту студент повинен:

1. Пояснити задум магазину та flow оформлення замовлення.
2. Обґрунтувати, чому кожне поле є обов’язковим або необов’язковим.
3. Показати правильне оформлення замовлення.
4. Продемонструвати щонайменше три неправильні сценарії.
5. Показати залежність між полями та пояснити її логіку.
6. Пояснити призначення `form`, `label`, `id` і `name`.
7. Пояснити різницю між `.value` і `.checked`.
8. Пояснити подію `submit` і `event.preventDefault()`.
9. Показати код перевірки даних, розрахунку вартості та підсумку.
10. Виконати невелику зміну за завданням викладача.

Приклади змін під час захисту:

- змінити одну складову вартості;
- змінити допустимий діапазон числового поля;
- додати новий варіант товару або послуги;
- змінити обов’язковість одного поля й пояснити наслідки;
- додати нову залежність між полями;
- змінити одне правило перевірки;
- додати нове поле до підсумку.

Можна використовувати AI, документацію та приклади, але студент повинен розуміти зданий код, уміти пояснити його та внести просту зміну.
